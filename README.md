# 수업 응답 웹앱

슬라이드를 띄우며 수업하고, 학생은 휴대폰이나 태블릿으로 그 쪽의 질문에 답하는 웹앱입니다.
교사는 화면에서 질문·설문·퀴즈를 직접 만들고, 응답을 실시간으로 모아 보고, 원하는 응답만 학생에게 공개합니다.

- **학생**: 수업 코드 + 반·번호 + 이름 + 숫자 4자리 비밀번호로 입장. 어느 기기에서든 이어서 씁니다.
- **교사**: 이메일과 비밀번호로 로그인. 수업 진행, 질문·설문 만들기, 학생 관리(비밀번호 초기화), 수업 설정.
- **비용**: GitHub Pages(화면)와 Supabase(데이터) 모두 무료 플랜으로 한 반 수업에 충분합니다.

---

## 파일 구성

| 파일 | 하는 일 | 고칠 일 |
|---|---|---|
| `index.html`, `student.js` | 학생 화면 | 없음 |
| `teacher.html`, `teacher.js` | 교사 화면 | 없음 |
| `common.js`, `app.css` | 두 화면이 함께 쓰는 기능과 모양 | 없음 |
| `config.js` | Supabase 연결 정보 | **2단계에서 고침** |
| `setup.sql` | 데이터베이스 표와 보안 규칙 | **1단계에서 교사 이메일만 고침** |
| `slides/` | 슬라이드 그림(1.png, 2.png …) | 내 PPT 그림으로 바꿈 |

## 1단계 · Supabase 만들기 (데이터 저장소)

1. [supabase.com](https://supabase.com)에 가입하고 **New project**를 누릅니다.
   - Region은 **Northeast Asia (Seoul)** 을 고르세요. 빠르고, 데이터가 국내에 있습니다.
   - Database Password는 아무 데나 적어 두세요(이 웹앱에서는 쓰지 않습니다).
2. 프로젝트가 만들어지면 왼쪽 메뉴의 **SQL Editor**를 엽니다.
3. `setup.sql` 파일을 메모장으로 열어 **맨 아래 줄의 `teacher@example.com`을 내 이메일(소문자)로 바꿉니다.**
4. 파일 전체를 복사해 SQL Editor에 붙여넣고 **Run**을 누릅니다. "Success"가 나오면 됩니다.
   - "destructive operation" 같은 경고 창이 나오면 그대로 실행을 누르세요(이미 있는 보안 규칙을 지우고 다시 만드는 줄 때문입니다).
5. 교사 계정 만들기: 왼쪽 메뉴 **Authentication → Users → Add user → Create new user**
   - 3번에 적은 이메일과 내가 쓸 비밀번호를 넣고, **Auto Confirm User**에 체크한 뒤 만듭니다.
6. (권장) 아무나 가입하지 못하게 막기: **Authentication → Sign In / Providers**에서 **Allow new users to sign up**을 끕니다.
   (꺼 두지 않아도 teachers 표에 없는 사람은 교사 화면을 쓸 수 없지만, 꺼 두는 편이 깔끔합니다.)

> 학생은 Supabase 로그인을 쓰지 않습니다. 그래서 익명 로그인 횟수 제한에 걸리지 않습니다.

## 2단계 · config.js에 연결 정보 넣기

1. Supabase 대시보드 위쪽의 **Connect** 버튼(또는 **Project Settings → API Keys / Data API**)에서 두 가지를 복사합니다.
   - **Project URL**: `https://abcdefgh.supabase.co` 모양
   - **Publishable key**: `sb_publishable_...` 모양
2. `config.js`를 메모장으로 열어 따옴표 안에 붙여넣고 저장합니다.

```js
const SUPABASE_URL = "https://abcdefgh.supabase.co";
const SUPABASE_KEY = "sb_publishable_xxxxxxxx";
```

> ⚠️ **secret 키(`sb_secret_...`, 예전 이름 service_role)는 절대 넣지 마세요.** 그 키가 있으면 누구나 모든 데이터를 읽고 지울 수 있습니다.
> publishable 키는 공개되어도 괜찮습니다. 보안은 setup.sql의 규칙(RLS)이 지킵니다.

## 3단계 · GitHub에 올리기

1. [github.com](https://github.com)에 가입하고 오른쪽 위 **+ → New repository**를 누릅니다.
2. 저장소 이름(예: `class-response`)을 적고 **Public**을 고른 뒤 **Create repository**를 누릅니다.
3. 다음 화면의 **uploading an existing file** 링크를 누릅니다.
4. 이 폴더 안의 **파일과 `slides` 폴더를 모두** 끌어다 놓습니다(폴더 자체가 아니라 그 안의 것들).
5. 아래 **Commit changes**를 누릅니다.

> 무료 GitHub Pages는 저장소가 공개입니다. **학생 명단, 응답 CSV, 교과서 파일 같은 것은 절대 올리지 마세요.**
> 학생 응답은 GitHub가 아니라 Supabase에 저장되므로 저장소에는 남지 않습니다.

## 4단계 · GitHub Pages 켜기 (웹 주소 만들기)

1. 저장소의 **Settings → Pages**로 갑니다.
2. **Source**: Deploy from a branch, **Branch**: `main` / `(root)` 를 고르고 **Save**를 누릅니다.
3. 1~2분 뒤 같은 화면 위쪽에 주소가 나옵니다: `https://내아이디.github.io/class-response/`
   - 학생 화면: 그 주소 그대로
   - 교사 화면: 주소 끝에 `teacher.html` (예: `https://내아이디.github.io/class-response/teacher.html`)

## 5단계 · 시험해 보기 (꼭!)

1. 교사 화면에 로그인 → **수업 설정**에서 수업을 만듭니다(예: 코드 `3반`, 슬라이드 수 `3`).
2. **질문·설문 만들기**에서 질문을 하나 만듭니다.
3. **수업 진행 → 학생 접속 주소·QR**을 휴대폰으로 찍어 학생처럼 입장하고 답을 저장합니다.
4. 교사 화면에 그 응답이 몇 초 안에 뜨는지 확인합니다.
5. **실습 학교에 가면 그 학교 와이파이에서 3~4번을 다시 해 보세요.** 학교 방화벽이 막는 경우가 드물게 있습니다.

## 쓰는 법

### 수업 진행
- **다음 ▶ / ◀ 이전**(또는 키보드 ← →)으로 넘기면 학생 화면도 따라 넘어갑니다. 학생은 지나온 쪽으로만 돌아갈 수 있습니다.
- 오른쪽에 그 쪽의 응답이 3초마다 새로 모입니다. **학생에게 공개**를 누르면 학생 화면에도 친구들의 응답이 보입니다(기본은 이름 없이).
- **제출 마감**을 누르면 학생이 저장할 수 없습니다. 쓴 내용은 학생 기기에 남아 있다가 다시 열면 저장할 수 있습니다.
- **크게 보기**는 TV에 띄우기 좋은 큰 화면, **학생별 표**와 **CSV**는 누가 무엇을 냈는지 봅니다.

### 질문·설문 만들기
- **슬라이드 질문**: 정해진 쪽 아래에 나오는 질문
- **설문**: 정답이 없는 질문 묶음
- **퀴즈**: 정답을 표시하면 자동 채점. 한 번만 제출할 수 있고, 제출 뒤 정답과 해설을 보여 줄 수 있습니다.
- "어디에 보일까요?"에서 **슬라이드 쪽 아래** 또는 **언제든**(모든 쪽 아래 목록)을 고릅니다.
- 질문 종류: 하나 고르기, 여러 개 고르기, 짧은 글, 긴 글

### 학생 관리
- 학생이 비밀번호를 잊었거나 5번 틀려 잠기면 **비밀번호 초기화**를 누르세요. 쓴 답은 그대로 남고, 학생은 다음에 들어올 때 새 비밀번호를 정합니다.
- 장난으로 만든 이름은 **삭제**하면 그 응답도 함께 지워집니다.
- 비밀번호는 암호화되어 저장되므로 교사도 볼 수 없습니다.

### 여러 반
- **수업 설정 → 다른 반용으로 복제**를 누르면 질문은 그대로, 새 수업 코드로 복사됩니다. 반마다 학생과 응답은 따로 모입니다.

### 내 슬라이드 넣기
1. PowerPoint에서 **파일 → 내보내기 → 파일 형식 변경 → PNG** → **모든 슬라이드**로 저장합니다.
2. 그림 이름을 `1.png`, `2.png` … 로 바꿔 GitHub 저장소의 `slides` 폴더에 올립니다(같은 이름은 덮어씁니다).
   - 이름을 바꾸기 번거로우면, PowerPoint가 만든 이름(예: `슬라이드1.PNG`) 그대로 올리고 **수업 설정의 슬라이드 폴더 칸에 `slides/슬라이드{n}.PNG`** 라고 적으세요. `{n}` 자리에 쪽 번호가 들어갑니다. 대문자·소문자도 똑같아야 합니다.
3. **수업 설정**에서 슬라이드 수를 맞춥니다. 슬라이드 없이 설문만 하려면 0으로 둡니다.
- 수업마다 그림을 나누려면 `slides/3반` 같은 폴더를 만들어 올리고 슬라이드 폴더 칸에 그 이름을 적으세요.

## 꼭 알아 둘 것

- **개인정보**: 학생 이름을 외부 서비스에 모으는 것이므로, 쓰기 전에 **지도교사께 확인**을 받으세요. 이름 대신 번호나 별명으로 들어오게 해도 됩니다.
- **비밀번호 안내**: 학생에게 "휴대폰 비밀번호나 생일은 쓰지 말라"고 꼭 말해 주세요.
- **Supabase 무료 프로젝트는 1주일 동안 쓰지 않으면 일시 정지**됩니다. 오래 쉬었다면 수업 전날 대시보드에 들어가 **Restore**를 누르세요.
- **인터넷이 끊기면 수업이 멈춥니다.** 같은 질문을 종이 활동지로도 준비해 두면 안전합니다.
- 수업이 끝나면 **CSV로 응답을 내려받아** 보관하세요.

## 문제가 생겼을 때

| 증상 | 확인할 것 |
|---|---|
| "아직 연결되지 않았습니다" | `config.js`의 주소와 키를 넣고 GitHub에 다시 올렸는지 |
| 교사 로그인 뒤 "교사로 등록되지 않은 계정" | `setup.sql` 맨 아래 이메일이 로그인한 이메일과 같은지(소문자). 고쳐서 다시 Run |
| 교사 로그인이 안 됨 | Authentication → Users에 그 계정이 있고 Auto Confirm 했는지 |
| 학생이 "수업 코드를 찾지 못했습니다" | 수업 설정의 코드와 같은지. QR이나 링크로 들어오면 코드를 칠 필요가 없습니다 |
| 슬라이드가 안 보임 | 파일 이름과 폴더, 대문자·소문자가 정확한지. GitHub에 올린 뒤 1~2분 기다렸는지 |
| 학생이 저장이 안 됨 | 교사 화면에서 "제출 열기" 상태인지 |
| 고친 파일이 반영되지 않음 | GitHub에 올린 뒤 1~2분 기다리고 새로고침(Ctrl+F5) |

## 어떻게 만들어졌나 (궁금한 사람만)

- 화면은 빌드 과정이 없는 HTML·CSS·JavaScript입니다. 파일을 고치고 GitHub에 올리기만 하면 됩니다.
- 데이터는 Supabase(Postgres)의 표 네 개에 저장됩니다: `lessons`(수업), `activities`(질문 묶음), `students`(학생), `responses`(응답).
- 표는 교사만 읽고 쓸 수 있도록 RLS 규칙으로 잠겨 있고, 학생은 `student_enter`, `student_state`, `student_save` 세 함수로만 데이터에 접근합니다. 퀴즈 정답은 학생이 제출하기 전에는 학생 화면으로 보내지 않습니다.
- 학생 화면과 교사 화면은 3초마다 서버에서 새 상태를 받아 옵니다.
